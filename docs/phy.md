# Low/full-speed PHY

`Livt.Usb.IO.IUsb2Phy` is a synchronous byte/line-control boundary. Directions are
relative to the PHY provider. `Usb2Phy` derives timing from its inherited context.
It requires an exact multiple of 12 MHz and at least eight samples per full-speed
bit; unsupported clocks fail construction assertions and disable pad drive even
when assertions are stripped. See [clock configuration](clocking.md).
The packet engine shares its rising-edge clock
and reset. Cross to another clock only through an explicit adapter.

This is a project-specific contract informed by
[UTMI](https://www.intel.com/content/dam/www/public/us/en/documents/technical-specifications/usb2-transceiver-macrocell-interface-specification.pdf),
not a complete UTMI/ULPI implementation. It supports USB low speed (1.5 Mbit/s)
and full speed (12 Mbit/s). It does not implement high-speed negotiation, an analog
differential receiver, enumeration, PID validation or CRC checking.

## Components and ownership

| Component | Responsibility |
|---|---|
| `Usb2Phy` | Owns sampler, RX/TX paths, admission and both pad output enables |
| `Usb2LineReceiver` | Samples the pair, qualifies line states and recovers bit phase |
| `Usb2PacketReceiver` | SYNC recognition, NRZI decoding, unstuffing, byte events and EOP/errors |
| `Usb2PacketTransmitter` | SYNC, NRZI/stuffing, serialized bytes, EOP and low-speed keep-alive |

The board owns PLL, reset conditioning, actual I/O buffers, electrical settings
and pin constraints. One link owner supplies configuration and packet data. The
PHY has fixed, bounded shift registers and counters, with no packet RAM; storage
backend selection belongs to the packet/transfer buffers above it.

## Signal timing

| Signals | Contract |
|---|---|
| `speed` | Low or Full; change only with TX/RX idle and bus reset inactive. Unknown/High prohibit packets and keep-alive |
| `txValid`, `txData` | Packet bytes including PID and CRC; hold until a joint valid/ready edge |
| `txReady` | One byte is accepted on each rising edge with both valid and ready true |
| `txBusy` | Raised by first-byte/keep-alive acceptance, retained through EOP and final driven J |
| `rxActive` | A packet has started; remains true through the final valid byte |
| `rxValid`, `rxData` | Each active/valid edge carries one byte, including PID/CRC, excluding SYNC/EOP |
| `rxError` | Invalidates the whole packet; retained through active falling, until next start/cancellation |
| `lineState` | Synchronized physical pair, bit 1 D+, bit 0 D−: 0 SE0, 3 SE1 |
| `supportsLowSpeed`, `supportsFullSpeed` | Static capabilities, independent of attachment |
| `busReset` | Forces SE0; the link owns duration and transaction cancellation |
| `keepAliveRequest`, `keepAliveReady` | A joint rising edge accepts one low-speed EOP; packet requests have priority |

Dropping valid at a byte boundary requests EOP. Once started, the stream cannot
pause: keep supplying valid bytes until the intentional end. Scheduled memory or
CLI calls must not pace this path. Ready paces bytes; the mandatory stuffed zero
is inserted even after the last byte. Acceptance of that byte is not completion.
Wait for busy to clear before starting another packet.

RX cannot stall. Capture every active/valid byte and discard the entire packet on
PHY error, local overflow, invalid PID or CRC. Completion is active falling, with
error still observable. SYNC/error events can complete without bytes. Up to six
trailing decoded ones are accepted as EOP dribble; this never substitutes for
packet length and integrity checks in `Livt.Usb.Packets`.

Keep-alive is accepted only in low-speed idle mode, with no packet request. Drop
the request after acceptance. It drives two SE0 bits and one J bit, then releases.
Full-speed SOF is a packet generated by host scheduling, not this handshake.

## Timing budget

The implementation uses `context.TicksPer(12MHz)` clocks per full-speed bit and
`context.TicksPer(1500KHz)` per low-speed bit. TX EOP is two bit times of SE0
followed by one bit time of J. First-byte acceptance starts busy
and drives J for one clock before SYNC. No TX bytes are received as local RX.

A two-register pair sampler feeds qualification and edge tracking. Differential
transitions rephase the next sample near bit center. SE0 qualification requires
one third of a bit time, rounded up to whole samples (3/22 samples at 96 MHz).
Idle requires two bit times of J;
mode changes invalidate the old qualification. A response queued at receive EOP
must start within the 2..7.5-bit turnaround window. The producer must still
budget its decision latency; the PHY cannot guarantee a late host response.

Receiver timing must accommodate device-rate tolerances (full speed ±2500 ppm,
low speed ±15000 ppm), sampling phase, jitter, crossover and minimum receive EOP.
The host's reference clock must meet its own ±500 ppm requirement. Platform
integration supplies the selected clock and verifies its accuracy and jitter against
the physical implementation. Functional simulation does not model analog clock
or I/O behavior.

These budgets follow the USB-IF [USB 2.0 specification](https://www.usb.org/document-library/usb-20-specification),
sections 7.1.4 and 7.1.8–7.1.13, 7.1.18, and tables 7-9/7-10. Electrical pad
integration must satisfy differential sensitivity, rise/fall, crossover-voltage
and cable/load requirements independently of digital protocol behavior.

## Reset and recovery

Bus reset dominates packet and keep-alive requests, aborts RX/TX, and drives SE0
even with speed Unknown. Context reset takes higher priority and releases both
pad drivers while clearing active/valid/ready/busy/error. Capabilities remain
constant. Platform integration must release pad drive on clock loss independently
of the USB clock and coordinate reset release once the clock is stable.

The decoder rejects malformed SYNC, SE1, seven unstuffed ones, a missing mandatory
final stuffed bit, non-one partial-byte tails and oversized SE0. Recovery requires
qualified J idle. Reset is cancellation, not a valid packet completion.

## Compiler workaround

Sampler outputs are passed as primitive constructor signals to the decoder.
This avoids an unwanted output register introduced by the current compiler when
borrowing the whole component. No generated VHDL is patched.
